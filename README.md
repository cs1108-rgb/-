# 量測資訊 MeasureInformationOS — 量測資訊文章檢核

## Windows 免安裝：單一 HTML（建議）
1. 下載 [單檔 HTML 壓縮包](releases/MeasureInformationOS-HTML.zip)，全部解壓縮後只有一個 `MeasureInformationOS.html`。
2. 使用最新版 Edge 或 Chrome 雙擊開啟，不需安裝 Node.js，也不需要啟動命令視窗或伺服器。
3. 點「新增文章檢核」，選擇刊期及 `.docx` 文章，即可查看逐項錯誤與修改建議。

亦提供 [原始 HTML 檔案](releases/MeasureInformationOS.html)。GitHub 可能顯示原始碼，請使用「Download raw file」下載並保留 `.html` 副檔名，不要將副檔名改為 `.txt`。

Word 解析、檢核程式與 A4 指定範本皆包在 HTML 內，執行時不呼叫後端、不載入 CDN、不傳送文件至伺服器。圖表與文字檢核引擎與 Node.js 版共用。

### 單檔版歷史與備份
- 使用 IndexedDB 保存在目前瀏覽器，**資料不會自動寫回 HTML 檔案**。
- 更換瀏覽器／電腦、清除網站資料或移動 HTML 可能無法取回歷史，請固定使用同一瀏覽器並定期「匯出完整備份」。
- 完整 JSON 備份包含原始 Word、所有歷史結果與各次規則快照；在同檔版點「匯入備份」可合併還原。重複紀錄會略過，當前規則開關不覆寫。
- 「匯出完整報告（Excel）」產生 `.xlsx` 單筆報告，不是含原稿的完整歷史備份；完整歷史備份仍使用 JSON 以支援還原。
- 若瀏覽器禁用儲存，會顯示「暫存模式」，關閉前必須匯出備份。
- 單檔版不能直接讀取既有 SQLite；SQLite 模式的資料仍由原 Node.js 版管理。
- 如電腦的企業政策禁止本機 HTML、JavaScript 或儲存，需請資訊人員確認允許的使用方式，不應繞過政策。

### A4 指定範本套版與 Excel 報告
- 「依範本匯出 Word」從原稿另存標準 `.docx`，統一套用 **A4 直式（21 × 29.7 公分）**、附件邊界與頁首頁尾、標題／作者／內文／標題層級／文獻等段落版型。這是完整的範本套版，不僅修正檢查出的錯誤；即使停用檢核規則，輸出仍採同一套 A4 標準。
- 使用者的原始附件保留於 `templates/article-format.docx` 供來源追溯；依使用者指定的 A4 輸出需求整理的版型為 `templates/article-format-a4.docx`，介面下載與套版均使用這份 A4 版本。原始與輸出版型的 SHA-256 皆記錄於政策資訊。
- 可辨識的章節套用對應版型；原文順序與圖表資源保留，不補寫缺少章節，不加入範例作者或照片。缺少／不明的摘要、作者、章節與複雜圖表會列為人工確認。
- 頁首頁尾改採附件版型；來源的原始檔仍保留。文字方塊、浮動圖形、圖表位置、解析度及最終分頁仍需在 Word 檢閱。本功能不使用 Word 原生追蹤修訂模式。
- 「匯出完整報告（Excel）」產生真正 `.xlsx`，包含摘要、全部問題與建議、全部檢核項目、規則快照、文字摘錄。先產生 Word 再匯出 Excel，會另附套版紀錄、套版後待處理問題與注意事項。
- 原始歷史報告不覆寫。下載副本與 Excel 留存，將標準版 Word 重新上傳，可建立新版本檢核紀錄。
- 已驗證輸出可由獨立 XLSX／DOCX 讀取器讀取、封裝關聯完整且重複套版不累積樣式。Microsoft Office 最終渲染未於此環境實機驗證。

### 單檔版建置與驗證
開發者可執行 `npm run build:standalone` 重新產生 HTML 與只有一個 HTML 的 ZIP；使用者無需執行此命令。
已用瀏覽器攔截 HTML 載入並關閉網路，驗證 Word 上傳、原稿下載、規則／歷史重新載入、備份還原與去重、行動版及禁止儲存時的提示。載入後沒有 HTTP 請求。測試環境的瀏覽器管理政策封鎖 `file://`，所以 Windows 雙擊本機檔案仍待實機驗證。

## Windows Node.js 版（另一種選擇）
1. 下載 [Windows 本機程式包](releases/MeasureInformationOS-Windows.zip)，並全部解壓縮。
2. 安裝 [Node.js 24 LTS](https://nodejs.org/)。
3. 雙擊 `SETUP-WINDOWS.cmd`（首次需網路），完成後雙擊 `START-WINDOWS.cmd`。
4. 在自動開啟的瀏覽器點「新增文章檢核」即可上傳 Word。

程式在本機使用，不需要公開網站。詳見程式包內的 `Windows使用說明.txt`。

針對每 2–3 個月製作的「量測資訊」Word 文章，依使用者提供的撰文範本進行格式檢核。支援 `.docx` 上傳、問題逐項列示、文字摘錄、修訂建議、原稿下載、規則設定、歷史紀錄、Excel 報告匯出與格式修訂 Word 下載。

## 執行
需要 Node.js 24（內建 `node:sqlite`）。

```sh
npm ci --cache /workspace/.npm-cache
npm test
npm run dev
```
預設埠 3000，可用 `PORT` 覆寫。正式模式：`npm run build` 後 `npm start`。這是 Express 後端與 React 前端的完整網站，不能只將 `dist` 上傳到靜態網站平台就執行 Word 檢核及資料庫功能。

## 檢核依據
原始使用者範本位於 `templates/article-format.docx`；介面提供依使用者需求正規化的 `templates/article-format-a4.docx`。規則版本、來源檔名及範本 SHA-256 儲存在每次報告中。範本內文字規範優先於其實際樣式：原始檔本身有樣式差異與未替換的範例內容，並不保證上傳範本會全數通過。

- 字體：微軟正黑體；文章標題 32pt；作者、摘要及一般內文 12pt。
- 段落：左右對齊、1.2 倍行距；摘要及一般內文首行兩字元；Heading 3／4 下內文不縮排。
- 結構：標題、作者、摘要、結論、參考文獻、作者簡介與範例文字提示。
- 層級：讀取 Word 標題樣式及大綱層級，提示跳級。不要求每篇文章都必須有四層標題，也不強制範本未明訂的章節標題字級。
- 圖表：圖說在下、表題在上、唯一編號、內文引用及引用加粗。檢查嵌入圖片格式、建議寬度 8–12 cm，依像素／置入尺寸計算有效 DPI。

讀取 Word 的直接格式、樣式繼承及可解析的主題字體。上限為 10 MB、10,000 段及 80 MB 解壓縮總量。舊版 `.doc`、加密文件與無可編輯本文的掃描文件不支援。

## 結果語意與限制
自動符合率 = 自動通過 /（自動通過 + 明確錯誤）。警告、待人工確認與停用規則不計入分母。沒有執行任何自動檢核時顯示無分數；停用規則不代表通過。

摘要不加標題時，以作者之後的段落推定，需人工確認。段落編號包含空白段落與表格文字，不代表頁碼。圖片類型（彩色／線條圖）、浮動圖形實際版面、文字方塊、文獻出版資訊及文章論述需人工複核。一般彩色圖片低於 300 dpi 列為錯誤；線條圖須人工辨識並確認至少 600 dpi。檢核不代表出版核可。

## 歷史、遷移與備份
SQLite 位於 `data/measurements.sqlite`，不提交 Git。每次上傳保存原始 Word、文字摘錄、問題、逐項檢核、規則開關與規則版本。後續修改規則不會改寫舊報告。

啟動會以新增欄位方式遷移舊版資料庫，保留既有數值量測報告；它們明確標為舊版，不納入文章趨勢。`MEASURE_DATA_DIR` 可覆寫資料目錄，測試使用獨立暫存資料庫。

停止服務後備份整個 data 目錄；部署時使用持久磁碟。SQLite 適合單機小團隊，多人跨機或高併發時建議改為 PostgreSQL。

此版未提供帳號登入或角色權限。正式使用敏感文章前須加入驗證、授權與備份策略。平台尚未發布，需另行部署 Node.js 服務及持久資料庫。

## 驗證
`npm test` 另涵蓋 A4 輸出、範本邊界／頁首頁尾、資源關聯完整性、缺少章節提示、重複套版不累積樣式、真正 XLSX 報表、公式字串純文字保存、Word 格式修訂、原文與所有其他封裝檔案完整性、停用規則及重複執行的一致性，並涵蓋文章規則、字體與段落繼承、標題跳級、拆分粗體引用、圖片 DPI、格式錯誤、停用規則、實際範本、API 上傳、舊資料遷移、原稿下載、規則快照與重啟留存。`npm run build` 驗證前端建置。

## Windows 本機使用
安裝 Node.js 24 LTS，完整解壓程式後雙擊 `SETUP-WINDOWS.cmd`（首次需要網路下載套件），再雙擊 `START-WINDOWS.cmd`。啟動檔會檢查 Node.js 版本、必要套件及埠號，服務就緒後開啟瀏覽器。日常使用無需發布網站，也不需要網路檢核服務。詳見 `Windows使用說明.txt`。

`npm start` 使用跨平台的 Node 入口，預設只監聽 `127.0.0.1`；`npm run dev` 為雲端開發預設監聽 `0.0.0.0`。本機使用請執行 Windows 啟動檔或 `npm start`。`MEASURE_HOST` 可供部署時明確指定監聽位址。Windows 啟動檔固定使用 loopback，避免將未提供登入驗證的本機版暴露至區域網路。

最新補充規範：作者姓名以頓號「、」分隔；圖說置中且位於圖片下方。章節依 Heading 1「一、」、Heading 2「(一)」、Heading 3「1.」、Heading 4「(1)」使用，避免跳級。第一、二層下內文首行縮排兩字元，第三、四層下不縮排；內文均為微軟正黑體 12pt、1.2 倍行距、左右對齊。章節順序異常會提示，不自動重排內容。明確的中文姓名逗號／分號分隔會於套版改為頓號；混合單位等資訊須人工確認。介面小字整體增加 2px。

2026-10-22：更新至本次提供的撰文範本，來源檔與 A4 輸出版雜湊同步更新。作者簡介樣式改由實際段落尋找，不依賴舊範本段落位置。介面更新為深藍導覽、淺色編務卡片、撰文重點規範及較高對比文字，保留已加大的介面字級。

圖片補充規範：圖片與圖說均置中；圖說編號與說明之間為兩個半形空格，例如「圖一  說明」，不加頓號。Word 套版會修正圖說分隔，保留說明文字，並置中嵌入式圖片段落及浮動圖片的欄內水平位置；舊式圖形及最終版面仍需於 Word 確認。
